# ClashX feature-parity ledger

This ledger prevents visual or compile-only work from being described as
ClashX feature parity. A feature is complete only when its production path and
tests exist; a Debug UI-review fixture is not implementation evidence.

## Reference boundary

The archived community mirror identifies ClashX 1.118.0 as the last historical
release. A later AGPL community continuation currently publishes 1.140.0 and
documents configuration switching, proxy selection priority, menu-bar speed,
remote-config URL schemes, bypass settings, global shortcuts, and shell proxy
commands. Its README points advanced TUN, Fake-IP, modern protocols, and a
userspace netstack to a next-generation client.

AetherRoute does not copy either AGPL codebase. These projects are behavioral
references only; Apple lifecycle and UI remain Swift, while the reviewed
Apache-2.0 Rust fork remains a statically linked data plane.

## Current parity state

| Native M-series macOS app and menu bar | Implemented | Swift 6/SwiftUI/AppKit targets build arm64 warnings-as-errors locally and remotely |
| Rule / Global / Direct modes | Implemented | Persisted native selection is passed through the provider configuration codec |
| Native manual nodes | Implemented | A typed Swift model and native add/edit/delete/reorder flow cover HTTP, SOCKS5, Shadowsocks, VMess, VLESS, Trojan, Hysteria2, TUIC, AnyTLS, WireGuard, SSH, and ShadowQUIC. SSH accepts bounded user-selected inline OpenSSH keys and an optional passphrase without displaying key material. Validation precedes deterministic YAML compilation; imported profiles cannot cross the native-edit boundary; all 12 generated profiles start on both core surfaces with networking denied |
| Local YAML import | Implemented adapter | Clash-style YAML is accepted through bounded UTF-8 validation and executable-key rejection, then stored with AES-GCM in the App Group. File reading, validation, and encryption run off the main actor; cancellation remains available until the atomic catalog/mirror commit begins. A Release gate imports and activates 5,000 nodes in 0.112 seconds with 6,193,152 bytes of sampled peak RSS growth. The two user-supplied local fixtures, including the 46-node x2cloud export, pass import, subscription, and both-core startup checks with networking denied. The same large fixture drove a bounded-concurrency core fix so two 46-member health-check groups cannot exhaust macOS file descriptors. This is a targeted executable import adapter, not a promise to reproduce another client's complete configuration semantics or edit imported YAML as native nodes; real x2cloud outbound connectivity remains a separate isolated-network gate |
| HTTPS profile subscription | Implemented, signed runtime pending | Encrypted URL/validators, ETag and Last-Modified, HTTPS-only redirect policy, 10 MiB bound, atomic activation, and six-hour checks while disconnected. AetherRoute identifies itself while advertising Clash-compatible YAML capability so provider backends can select the format the bounded adapter accepts. The adapter preserves validated YAML or converts bounded plain/Base64 share-link lists for all 12 typed protocols into AetherRoute's canonical profile. Valid nodes are imported while malformed or unsupported entries are skipped and reported; an all-invalid list still fails without replacing the active profile. Executable YAML remains rejected as a whole. An x2cloud Shadowsocks export with an empty trailing query marker passes the full isolated subscription and both-core startup pipeline with networking denied; temporary response data is removed and the host network-control fingerprint remains unchanged. Selective recovery inside arbitrary YAML remains intentionally out of scope until a complete bounded YAML model can prove that removing one entry cannot alter routing semantics. |
| Multiple named profiles and fast switching | Implemented | AES-GCM catalog stores up to 64 validated local/subscription profiles; migrate, rename, delete-inactive, switch, mirror-repair, tamper, and purpose-separated AAD tests pass |
| Cross-machine profile transfer | Implemented | Explicit `.aetherroute` export/import uses PBKDF2-HMAC-SHA256 (600k iterations) and AES-256-GCM; the device-only Keychain key is never exported, local active selection is preserved, and duplicates/identifier collisions are resolved |
| URL-scheme subscription import/update | Implemented | AetherRoute registers `aetherroute://subscribe?url=…`. The bounded parser accepts exactly one credential-free, fragment-free HTTPS target; an external event only stages a request. A native confirmation sheet shows the provider host while hiding query tokens, makes no request before consent, and requires an explicit user action before the existing validated encrypted import path can download or activate anything |
| Proxy-group node selection | Implemented, signed runtime pending | Both providers expose bounded ARQ1/ARP1 snapshots and live selection; the host verifies the selected member by rereading core state and persists only provider-confirmed choices in profile-digest-bound AES-256-GCM storage |
| Batch latency testing | Implemented, signed runtime pending | A user action sends a bounded HTTPS URL/timeout command through ARQ1/ARP1; both providers call the real outbound handlers through the ARL1 Rust ABI, preserve per-member failures, and return at most 1 MiB. No background probe runs |
| Live connection list, upload/download, rule hits | Implemented, signed runtime pending | Both cores export the versioned `ART1` snapshot through their provider message path. The host renders live totals, rules, payloads, and proxy chains; a signed-provider proof remains open |

| Modern protocol data plane | Integrated; final 24-hour gate pending | `Config/ProtocolReleaseMatrix.json` maps all 12 catalog protocols to 21 protocol/transport cases and four additional independent runners/tests. The pinned source-build matrix plus independent VLESS REALITY, WireGuard, ShadowQUIC, and OpenSSH gates pass. Both current `4b03bf8` core artifacts start all 12 typed node families and 48 bounded input variants on FlowOnly and PacketFlow with networking denied; the two black boxes also deliver 10,000 numbered loopback UDP payloads each after 32 warm-ups with zero missing or duplicates. The first historical 24-hour attempt stopped at FlowOnly round 405, and the later schema-1 run produced no recoverable verifier-backed result, so neither is release evidence. Packet Tunnel passes those validated fixed-width fields through a versioned C ABI after YAML parsing; it never rewrites imported YAML or crosses endpoint/domain bytes.
