# ClashX feature-parity ledger (historical validation snapshot)

> Status reconciliation, 2026-09-17: the detailed table below is historical,
> not a current release certificate. Later 1.0.12 release notes record signed
> distribution and VM runs; this review has not revalidated those packages.
> Current default distribution is free with Sparkle updates. Engine changes
> use stop-and-reconnect, not seamless flow migration. Route preview supports
> basic destination rules and reports indeterminate for runtime-dependent or
> truncated rules. TUN domain bypass remains unsupported (CIDRs only).
> Physical sleep/wake, genuine default-uplink handoff and real-network soak
> need artifact-bound evidence; lock notification and VM-freeze tests are
> separate scopes. See CodeReview-2026-09-17.zh-CN.md for the original findings
> and ReviewFixes-2026-09-17.zh-CN.md for changes and current validation.


This ledger prevents visual or compile-only work from being described as
ClashX feature parity. A feature is complete only when its production path and
tests exist; a Debug UI-review fixture is not implementation evidence.

## Reference boundary

The archived community mirror identifies ClashX 1.118.0 as the last historical
release. A later AGPL community continuation currently publishes 1.140.0 and
documents configuration switching, proxy selection priority, menu-bar speed,
remote-config URL schemes, bypass settings, global shortcuts, and shell proxy
commands. Its README points advanced TUN, Fake-IP, modern protocols, and a
userspace netstack to a next-generation client.

AetherRoute does not copy either AGPL codebase. These projects are behavioral
references only; Apple lifecycle and UI remain Swift, while the reviewed
Apache-2.0 Rust fork remains a statically linked data plane.

Valid nodes are imported while malformed or unsupported entries are skipped and reported; an all-invalid list still fails without replacing the active profile. Executable YAML remains rejected as a whole. An x2cloud Shadowsocks export with an empty trailing query marker passes the full isolated subscription and both-core startup pipeline with networking denied; temporary response data is removed and the host network-control fingerprint remains unchanged.
