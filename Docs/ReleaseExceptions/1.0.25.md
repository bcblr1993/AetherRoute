# v1.0.25 发布验收说明

2026-09-23，完成 Tailscale 与虚拟覆盖网络底层路由冲突修复、Core 引擎睡眠唤醒时钟健壮性优化、Tart 虚拟机 6 维网络矩阵验证及 Apple Silicon 物理真机全量回归测试：

### 核心优化与演进落地：

1. **彻底解决 Tailscale 与虚拟网络底层静态路由劫持（`PacketTunnelNetworkSettingsPlan.swift` & `PacketTunnelProvider.swift`）**：
   - 深度溯源并解决 macOS Darwin 内核对 NetworkExtension `excludedRoutes` 的选路机制：当任何 CIDR 被置于 `excludedRoutes` 时，系统内核会强制添加一条指向物理以太网/Wi-Fi 默认网关的非 scoped 静态路由（`UGSc`，例如 `100.64/10 -> 10.8.7.254 on en11`）；
   - 该全局静态路由劫持了属于 Tailscale 虚拟网卡 `utun4` 的覆盖网络，导致发往 Tailscale 节点（如 `100.64.0.3`）的数据包被错误发送至物理局域网网关后丢弃（造成 SSH 及对端超时）；
   - 正确解耦虚拟覆盖网络与内核物理排除网段：正式将 `100.64.0.0/10` 及自定义 CIDR 从 `PacketTunnelNetworkSettingsPlan.swift` 的 `excludedRoutes` 中完全移除，仅保留真正的物理 LAN 网段（RFC 1918）；
   - Tailscale 流量的直连保护完全交由 Clash 引擎层（[`DomesticRoutingOptimizer.swift`](file:///Users/chenxu/IdeaProjects/AetherRoute/Sources/AetherRouteKit/DomesticRoutingOptimizer.swift)）内置的 `IP-CIDR,100.64.0.0/10,DIRECT,no-resolve` 及 Fake-IP Filter 避让机制保障。系统内核不再添加冲突静态路由，Tailscale peer 间直连与 SSH 访问完全恢复秒级通畅。

2. **Core 引擎时钟单调性防 panic 优化与证据链同步（`Core/Engine` & `ProtocolCoreEvidence.json`）**：
   - 合并核心引擎提交 `7bb5f30`：在系统睡眠与唤醒跨周期场景下，将所有可能产生负向时钟偏差的 `Instant::duration_since` 统一优化为 `saturating_duration_since`，从底层杜绝时钟漂移引发的 panic；
   - 同步更新并锁定 `ProtocolCoreEvidence.json` 与 `ThirdPartyLicenses.json` 的生产核心 SHA-256 哈希值与源码提交点，严格保障供应链完整性与协议证据链闭环。
