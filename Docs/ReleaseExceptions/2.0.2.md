# 2.0.2 验收与边界

目标构建：2026110201，发布日期 2026-11-02。0105 验收全部通过后，发布前安全核对发现当前 Rust 依赖命中告警，未对外发布；以下 0105 结果保留为阶段证据，0201 须重新完成核心及硬件验收。

## 已复现并修复

- 远端 TCP 半关闭后，固定计时器会取消仍在上传的连接；现按单调时钟的实际空闲时间回收，等待在途写入。
- 透明代理 TCP/UDP 汇总字节与失败计数缺少生产者，半关闭超时在标准日志不可见；现按成功确认计量并记录明确终止原因。
- 菜单栏延迟文字绘制在变化变换下持续保留缓存。3,000 次绘制中，旧实现预热后增长约 37 MB，新实现约 0.15 MB；新增自动内存回归和跨绘制外观的对比度回归。
- 实验室源码部署不完整、固定的 VLESS 加密密钥不匹配、覆盖运行中程序报 ETXTBSY；均有先失败后通过的回归与实际部署验证。
- 远程源码快照会复制验证不需要的 Sparkle 私钥与签名配置，现从清单及复制路径排除，公钥仍随源码验证；合成密钥回归先失败后通过。

## 首轮矩阵阻断及验证脚本修正

构建 2026110101 的首轮矩阵有一项失败：透明代理／直连的公共 Cloudflare HTTP 突发探测 1/60 超时。该轮未发布。

关闭 VM 内 AetherRoute 后，对同一端点进行固定三轮对照。插桩捕获两次约 10.2 秒的响应头读取超时；旧脚本因内部重试仍报告 60/60 通过。因此公共端点的瞬态失败不能直接当作候选软件的并发故障。

脚本现使用 60 个同步起跑的 worker，取消隐藏重试；发布矩阵使用实验室独立的空响应 HTTP 源并验证响应身份，隔离公共 CDN 的可用性。并发数、超时和内存预算没有放宽。默认诊断调用仍可使用公共端点。

新增源曾与 Shadow TLS 的内部监听端口冲突，已将内部监听纳入清单与端口冲突回归，改用保留范围内的空闲端口。该问题仅发生于本次实验室准备阶段，未发布候选软件。

构建 2026110102 使用受控源后的首次矩阵仍阻断：透明代理／全局模式 1/60 在响应头阶段超时。对应终止记录为请求 141 字节已交给核心，约 10.27 秒后读到 162 字节响应，但客户端已超时关闭，未成功回写。该结果保留，不作通过处理。

随后关闭 VM 内 App，以相同导入配置的首个 VLESS REALITY 节点运行独立 Mihomo 与本项目核心，每方固定五轮、每轮 60 个同步请求、10 秒客户端期限、无重试。Mihomo 300 次失败 21 次，本项目独立核心失败 23 次；另设只记录合成请求编号与时间的 HTTP 源，捕获到个别请求在客户端期限后才到达。因此该上游路径在扩展之外也不稳定，不能据此认定透明代理存在独有丢包。该节点的 REALITY 使用外部 Cloudflare 伪装目标；外部链路与节点内部的具体责任尚未唯一确定，未修改该既有节点服务。

切换受控配置的首次尝试发现验证脚本的另一个缺陷：预热会重写 `debug_profile_optimized.yaml`，原脚本在评分时才读取它，实际仍可能测到旧配置；其远程命令对带空格的路径也缺少正确引用。该轮中止，不能作为受控配置的验收结论。新增完整驱动行为回归，模拟预热覆盖文件，先在旧驱动失败；现于预热之前复制权限 0600 的不可变夹具、记录 SHA-256，所有评分组合导入同一暂存文件，九种准备／失败／清理场景均通过。回归已在完整 `test.sh` 中执行。

进一步核对实际生效配置，又复现 QA 启动流程没有等待异步导入、且正常启动恢复可与 QA 导入并发的缺陷。编译并执行实际启动分支的回归分别在旧分支失败；修复后等待导入完成、拒绝失败或未开始的导入，显式 QA 启动由 QA 流程独占自动连接。不可变夹具放在 App Group 内供沙盒读取，清理时删除。上述变更仅影响 QA 自动化构建；构建号推进至 0103，重新构建候选并执行完整验收。

0103 的实际生效原文 SHA-256 已与受控 JSON 夹具逐字节匹配，但核心启动失败。这次暴露的是运行时兼容性缺陷：导入验证接受 JSON Clash 配置，国内路由优化却按块状 YAML 分节，生成混合的无效配置。新增回归在旧实现失败；现仅将运行时副本转成块状 YAML，原始导入文本不变，三条优化路径都验证嵌套参数完整往返。

0104 随后的真实启动发现 JSON 字符串默认输出 `\/`，DNS 按行处理后把转义保留在 DoH 地址，核心拒绝无效解析器。新增包含 DoH、带代理片段的 fallback 和多解析器策略的回归，旧实现因解析器 URL 改变失败；运行时 JSON 标量现保留普通斜线，并在发布前使用真实核心检查转换后的三个配置。0104 未发布。

该失败还暴露配置错误会将完整文本或 serde 拒绝的输入值带入返回值和日志。Rust 配置解析现只返回固定阶段及可用的行列号，普通／严格模式、语法／锚点／类型／节点四种失败都有先红后绿的隐私回归。旧诊断原文仅保留在权限受限的本次私有排查目录，不作为公开附件。0103 已停止，受影响的构建均未发布；随后推进至 0104，再因上述 URI 回归推进至最终 0105；Rust 核心全套必需门禁已重跑。

最终六维矩阵使用本次实验室受监督的 Shadowsocks AES-128-GCM 节点和同一受控 HTTP 源，完整重跑所有组合；这隔离了不稳定上游，并不降低 60 并发、10 秒期限、零重试和内存预算。协议兼容仍由默认／Chrome 全矩阵、真实站点和 43 节点 Mihomo 对照独立验证。VM 的原偏好和配置文件在结束后恢复。最终证据保留于 `outputs/acceptance-2.0.2-2026110105/`，各次失败的报告仍保留在原构建目录。

远程源码门禁使用新编译的协议测试二进制，而非旁路旧缓存。显式覆盖路径必须存在且可执行，复制强制校验内容 SHA；同大小、同时间戳但内容不同的旧缓存回归先失败后通过。最终二进制与核心提交及源码 blob 的绑定保留于 `outputs/json-runtime-privacy-fix-20261101/verified-core-bindings.json`。

物理机收尾发现上传的候选 DMG 因 `/tmp` 为符号链接而未被原 `find /tmp` 清除。执行真实清理命令的合成目录回归先复现残留，再验证按精确文件路径删除、保留其他构建及目录链接。此修正仅涉及打包之外的清理脚本，App 二进制与已验收 DMG 不变；最终完整本地和 VM 源码门禁均已纳入并通过该回归。
