# 2.9.2 验收与边界

发布构建：`2026111004`。Rust 核心提交 `df30585e7265e5dea2149e29fbc94e1fa5888f57`（`df30585`），重点修复卸载重装后未重启 Mac 时，首次运行网络扩展向导（`NetworkSetupView`）因 `sysextd` 残留跨版本 `[terminated waiting to uninstall on reboot]` 条目及双引擎串行等待导致卡死在「正在等待授权...」无法进入下一步的问题。

## 核心修复与优化

1. **跨版本待重启卸载状态（`[terminated waiting to uninstall on reboot]`）精准识别（`SystemExtensionActivationPolicy.swift`、`SystemExtensionActivationCoordinator.swift`）**
   - **根因**：对 macOS `sysextd` 与 `ExtensionKitSettings.framework`（`LoginItems.appex`）反汇编分析证实，当用户在旧版本（如 `2.9.0` / `2.9.1`）执行过卸载但尚未重启 Mac 时，`/Library/SystemExtensions/db.plist` 中仍保留旧版本 `stagedBundleURL != nil` 且状态为 `terminated_waiting_to_uninstall_on_reboot`（`enabled = false`）的记录。此时「系统设置 > 通用 > 登录项与扩展 > 网络扩展」中的 `SystemExtensionsModel` 调用 `[OSSystemExtensionClient listAllExtensions:]` 会把已停用待重启的旧条目一并列出，并在点击开关时触发 `OSSystemExtensionErrorDomain Code=4`（Extension not found）。原 `SystemExtensionActivationPolicy.requiresRebootBeforeReinstall` 仅在 `$0.version == expected` 完全相等时判定需要重启，导致升级到新构建号后漏检跨版本的 `isUninstalling` 记录，持续向 `sysextd` 发起挂起的激活请求。
   - **TDD 修复**：更新 `SystemExtensionActivationPolicy.requiresRebootBeforeReinstall(expected:installations:)`，只要同一扩展标识符（`$0.version.identifier == expected.identifier`）下没有任何处于已启用活跃态（`isEnabled && !isAwaitingUserApproval && !isUninstalling`）的记录，且存在任意版本处于 `isUninstalling == true`（`[terminated waiting to uninstall on reboot]`），即立即判定为 `.rebootRequired`（若已有活跃启用版本，则正常放行平滑热升级）；并在 `SystemExtensionActivationCoordinator` 的 `foundProperties` 与 `SystemExtensionStatusProbe` 中统一拦截提示。

2. **双引擎独立并发初始化与单引擎就绪即可「继续」（`TunnelManager+NetworkSetup.swift`、`NetworkSetupProgress.swift`、`NetworkSetupView.swift`）**
   - **根因**：原 `TunnelManager.runNetworkSetup()` 先串行等待两个扩展的 `installExtensionForSetup` 全部返回后才执行 `saveConfigurationForSetup`，且 `NetworkSetupProgress.canFinish` 要求尚未就绪的另一引擎不能处于 `.awaitingApproval`，导致即使 `TUN` 已经授权就绪（显示绿色对勾 `✅`），只要 `透明代理` 仍在等待授权或因未重启无法开启，底部按钮就会一直灰置显示「正在等待授权...」，无法进入主界面。同时 `refreshNetworkSetupStatus()` 中的 `guard !isRunningNetworkSetup else { return }` 阻止了从「系统设置」切回 App 时的状态刷新。
   - **TDD 修复**：
     - 将 `runNetworkSetup()` 改为按引擎并发独立执行：任一引擎（如 `TUN`）完成扩展激活后立即保存其 NetworkExtension 配置并进入 `.ready`（`✅`），不再被另一引擎阻塞。
     - 更新 `NetworkSetupProgress.canFinish(_:)` 与 `detectedState(extension:hasConfiguration:)`：只要至少一个引擎已达到 `.ready`，无论另一个引擎处于 `.ready`、`.rebootRequired`、`.isBlockedPermanently` 还是 `.awaitingApproval`，底部主按钮立即变为可点击的「继续」，点击后 `finishNetworkSetup()` 自动将默认网络引擎切换至已就绪的引擎（如 `TUN`）。
     - 移除 `refreshNetworkSetupStatus()` 的 `isRunningNetworkSetup` 拦截，并在 `SystemExtensionActivationCoordinator` 中监听 `NSApplicationDidBecomeActiveNotification`，用户从「系统设置」切回 App 窗口时立即探测并刷新扩展状态。
