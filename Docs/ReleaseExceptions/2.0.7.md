# 2.0.7 验收与边界

发布构建：`2026110501`。Rust 核心提交 `ba3d404c092ff2165cb982eafcaf1833574d2321`（`ba3d404`），基于本机连续 8.5 小时（30 秒/次，共 1,020 个采样点）的全量运行时遥测监控分析，采用 TDD（测试先行）修复全部 4 项根因问题（1 项 `P1_CRITICAL`、3 项 `P2_WARNING`）并通过核心回归、双指纹 12 协议互通、43 节点 Mihomo 实验室对照及真机 UI 性能与内存预算门禁验证。

## 8.5 小时连续遥测根因修复与测试先行（TDD）

1. **P1_CRITICAL：主进程 `CGFontCache` 锯齿形内存泄漏（`174 MB -> 378 MB`）与 UI 性能门禁盲区修复**
   - **根因定位**：8.5 小时监控（1,020 采样）显示主进程 `Physical Footprint` 以 `+42.5 MB/h` 锯齿形上涨至 `378 MB`（`Malloc Small` 从 `58.9 MB` 涨至 `244.6 MB`，`heap non-object` 节点从 `26,340` 涨至 `96,498`），`malloc_history` 定位到 `libFontRegistry.dylib` 的 `CGFontCacheGetLocalCache.local_font_cache` 持续累积 `2,048–2,560 Bytes` 的可变字体 `CGFont` 实例。原因是 `AetherNumericValueModifier`（`Sources/AetherRouteApp/AetherMotion.swift`）使用了 `.contentTransition(.numericText(countsDown: countsDown))`，当菜单栏与主窗口开启时，`ConnectionCountBadge`、`ProxyLatencyText` 与 `DNSPageView` 在连接数和延迟变化时每秒生成中间插值字形且不被 `CGFontCache` 及时回收。
   - **修复方案**：将 `AetherNumericValueModifier` 统一改为 `.contentTransition(.identity)`，彻底消除滚动数字插值触发的 `CGFont` 缓存堆积；同时更新 `Sources/AetherRouteApp/TunnelManager+Telemetry.swift` 的 `advancedReviewSnapshot`，在 `AETHERROUTE_UI_REVIEW_LIVE=1` 性能压测模式下每秒交替注入 `review-transient-flow.example`，使 `connections.count` 在 `N <-> N+1` 间真实跳动，补齐 `ConnectionCountBadge` 动态刷新覆盖。
   - **TDD 验证**：扩展 `scripts/test_motion_guards.sh` 与 `scripts/test_telemetry_observation_scope.sh`，在旧代码上立即失败（检出 `.contentTransition(.numericText` 及静态连接数），修复后通过。

2. **P2_WARNING：Fake-IP 二级历史反向映射保持与 HTTP/MMTLS Host 自愈（`fakeIpMappingMissing` 阶梯式 `+9/h`）**
   - **根因定位**：监控期间 `fakeIpMappingMissing` 每小时稳定增加约 `9` 次（`24 -> 101`）。一是当域名 `D` 的 DNS TTL 到期重新分配了新主 Fake-IP `IP_new` 后，长连接或缓存仍向旧 Fake-IP `IP_old` 发起连接时，旧版 `FakeDns::restore_if_unmapped` 因 `self.host_to_ip.contains_key(host)` 提前返回 `false`，拒绝恢复 `IP_old -> D` 的二级反向映射；二是微信后台 `POST /mmtls/...` 等明文 HTTP 协议使用 `Host:` 头而非 TLS SNI，旧版 `peek_client_hello_sni` 仅解析 `0x16` TLS ClientHello。
   - **修复方案**：更新 `Core/Engine/clash-lib/src/app/dns/fakeip/mod.rs`、`mem_store.rs` 与 `encrypted_store.rs`，允许在不覆盖当前主正向映射 `D -> IP_new` 的前提下恢复并持久化 `IP_old -> D` 二级反向映射；在 `fake_ip_sni.rs` 与 `dispatcher_impl.rs` 中新增 `sniff_client_hello_or_http_host`，在 443 与 80 端口同时支持从 TLS ClientHello SNI 及 HTTP/MMTLS `Host:` 请求头恢复域名并自动自愈未映射 Fake-IP。
   - **TDD 验证**：新增 3 项 Rust 单元测试（`test_restore_if_unmapped_preserves_primary_ip_while_restoring_secondary_reverse_mapping`、`secondary_restored_mapping_survives_encrypted_store_reload_without_clobbering_primary`、`client_hello_or_http_host_recovers_both_tls_sni_and_mmtls_http_host`），在旧代码上 `0 passed; 3 failed`，修复后 `3 passed; 0 failed`。

3. **P2_WARNING：Tunnel 启动阶段 `182.818 notifications/sec` CoreFoundation 通知风暴治理**
   - **根因定位**：`RoutingResourceStore.prepareRuntimeResources`（`Sources/AetherRouteKit/RoutingResources.swift`）每次启动在临时 `.staging-<UUID>` 目录与正式运行目录对每个文件无条件调用 `URL.setResourceValues(isExcludedFromBackup = true)` 及 `.atomic` 覆写，触发 `CFPrefsManagedSource` / `filecoordinationd` 分布式通知风暴。
   - **修复方案**：跳过临时 `.staging-<UUID>` 目录的 `excludeFromBackup` 设置；在正式目录设置前先通过 `getxattr(url.path, "com.apple.metadata:com_apple_backup_excludeItem", nil, 0, 0, XATTR_NOFOLLOW) > 0` 短路已具备排除扩展属性的路径；在 `writeProtected`（含 `TransparentProxyRuntimeInput.swift`）中比对现有文件字节一致时直接复用原文件与 inode，仅校准 `0600` 权限与备份排除标记。
   - **TDD 验证**：`RoutingResourceStoreTests` 新增 `testPrepareRuntimeResourcesPreservesUnchangedRuntimeInodesAndBackupExclusion`，在旧代码上因每次重写更换 inode 失败，修复后通过。

4. **P2_WARNING：主进程启动阶段 AppKit 布局递归（`_NSDetectedLayoutRecursion`）消除**
   - **根因定位**：`WindowChromeView`（`Sources/AetherRouteApp/AetherRouteApp.swift`）在 `updateNSView` 和 `viewDidMoveToWindow` 中同步修改 `window.titleVisibility`、`toolbarStyle` 与 `toolbar.showsBaselineSeparator`，而 `updateNSView` 恰在 `NSWindow.layoutIfNeeded()` 布局遍历期间执行，引发重入布局警告。
   - **修复方案**：引入 `scheduleApplyWindowChrome()`，将同一 RunLoop 周期内的窗口样式更新合并并通过 `DispatchQueue.main.async` 推迟至当前布局周期结束后执行。
   - **TDD 验证**：扩展 `Tests/WindowVisibility/run.sh` 静态与运行时门禁，旧代码失败、新代码通过。

5. **核心与主进程实时物理内存遥测可视化**
   - `TrafficHistory` 与 `NetworkTelemetryViewModel` 同步采集引擎核心内存与宿主 App 的 Mach `TASK_VM_INFO` `phys_footprint`（`ProcessMemoryFootprint`），在菜单栏状态弹窗、概览页及连接页状态栏展示 Core 与 App 实时物理内存占用及趋势曲线，并由 `Tests/TrafficHistory/main.swift` 覆盖验证。
