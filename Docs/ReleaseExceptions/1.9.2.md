# v1.9.2 发布验收说明

2026-10-28，透明代理在节点全部失效时，测速不再阻塞控制通道，也不再引发扩展重启。正式构建 2026102804（stable 通道，Normal Core，引擎 `ad7bac5`，与 1.9.1 相同）。

## 变更内容

- `TransparentProxyProviderRuntime`：测速改为在 `controlLock` 之外执行，与 TUN 一致；测速仍然计入进行中的控制调用，停止时会等它结束后再关闭引擎。
- `ProviderMessageClass.countsTowardUnresponsiveProvider`：只有控制类消息（快照、遥测、选节点）超时才计入"扩展无响应"，测速超时不计入。

## 例外

### 1. 并行验收中远程 ARM64 门禁因 SSH 中断退出，已单独重跑并通过

并行验收（`outputs/acceptance-1.9.2-2026102804`）中，VM 6 维矩阵全部通过。物理机轨道以 255 退出，日志为 `Timeout, server 100.64.0.3 not responding`，中断之前的所有检查项均为 PASS。当时本机使用 iPhone 热点，只能经 Tailscale DERP 中继连接 Mac mini，SSH 中途断开。

清理掉中断残留的 463 MB 远程工作目录后，按 SOP 单独重跑了 `AETHERROUTE_ALLOW_REMOTE_GATE=YES ./scripts/test_remote_arm64.sh chenxu@100.64.0.3 fast`，结果通过（`outputs/test-evidence/remote-arm64-20261028T082707Z-fast`）。随后执行 `./scripts/test_ui_performance_gate.sh`，结果同样通过（`outputs/perf-gate-1.9.2-2026102804`）。
