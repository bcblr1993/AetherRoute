# v1.0.32 发布验收说明

2026-09-28，完成长连接空闲复用优化（Keep-Alive 60s 断开根因修复）、Tracked Stream 释放竞态修复、TUN 模式热重载 Fake-IP 缓存继承修复、Root 权限网络扩展诊断日志级别透传、数据面 30 秒采样遥测、Tart 虚拟机 `macos27` 6 维矩阵验收与空闲复用门禁、物理真机全矩阵回归验证：

### 核心优化与演进落地：

1. **长连接空闲复用机制重构（`Core/Engine` Dispatcher）**：
   - TUN 与本地 HTTP/SOCKS 流量此前沿用上游 Relay 策略，导致静默 60 秒后连接被单方面断开；对于使用连接池的客户端（如 Claude Desktop / Claude Code），复用已关闭连接会触发 `ECONNRESET` 异常；
   - 调整本地客户端入站保持策略，与透明代理对齐，由底层 TCP Keep-Alive 栈负责死亡对端回收，保持客户端空闲池可用性。

2. **Tracked Stream 关闭竞态 Panic 消除（`Core/Engine` Tracked Stream）**：
   - 修复在连接管理器已关闭连接后，被追踪的流仍继续轮询已完成关闭通知的问题，彻底消除连接析构竞争异常。

3. **TUN 热重载 Fake-IP 缓存保护（`Core/Engine` Configuration Reload）**：
   - 修复在 TUN 模式下动态重载配置或自定义分流规则时，重载快照未正确传递 Fake-IP 缓存密钥导致键长检查失败、连接假死的问题；重载快照现完全继承启动快照密钥。

4. **网络扩展诊断日志级别透传（Network Extensions Launch Snapshot）**：
   - 由于两个 Network System Extensions 均以 root 权限运行，无法读取用户 App Group 容器内的级别文件；主程序现通过启动快照（Launch Snapshot）显式传递诊断级别。

5. **数据面低侵入遥测采样（Packet Tunnel Data-Plane Telemetry）**：
   - 在标准诊断级别下，Packet Tunnel 扩展每 30 秒记录一行运行时数据面指标（连接数、流量统计、TCP 连接错误、Fake-IP 映射/反查失败计数、网络重置数、内存开销及句柄占用）；在 Verbose 级别下附带当前活动连接与代理链细节。

6. **长连接空闲复用验收门禁落地（`scripts/test_idle_keepalive_reuse.sh`）**：
   - 新增专用门禁脚本，针对真实 TLS 连接在静默 50 秒后再次发送请求，断言连接正常复用（避免被中间 Relay 截断）；已纳入虚拟机矩阵与物理机测试标准。

7. **版本号推进与项目规范对齐（`project.yml`、`CHANGELOG.md`）**：
   - 版本号推进至 `MARKETING_VERSION: "1.0.32"`, `CURRENT_PROJECT_VERSION: "2026092801"`。
