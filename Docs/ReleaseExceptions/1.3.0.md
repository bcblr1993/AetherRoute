# v1.3.0 发布验收说明

2026-10-06，功能版本：连接页显示每条连接的来源应用（可按应用分组、筛选）；新增应用规则，可让某个应用始终直连、走指定代理组或拒绝，优先于其他所有规则；配置中的 `PROCESS-NAME` / `PROCESS-PATH` / `PROCESS-PATH-REGEX` 规则可用。引擎 aetherroute-core `0b6c24c`。

### 验证结论

1. **本地回归**：`test_network_switch_gate.py`、`Tests/EngineReconnect/run.sh`、`Tests/RuntimeEnvironment/run.sh`、`./scripts/test.sh` 全部通过，零编译警告；App 单元测试 404 + 84 + 22 全部通过（新增 20 个）；引擎 clash-ffi 测试 37（透明代理）+ 55（TUN）通过。
2. **协议互通门禁（release）**：每次引擎改动后 5 项全部 PASS（最终一轮 `outputs/interop-20261005T170316Z`）。
3. **物理真机矩阵（Mac mini，局域网 192.168.50.226，代替虚拟机）**：公证正式候选包 2026100602 以 `test_runtime_acceptance.sh` 验收 tun / transparent × rule / global / direct 共 6 个组合，全部通过、无失败项；空闲复用 6/6、2 MiB 上传 6/6、透明代理 SNI 恢复 3/3。报告见 `outputs/release-1.3.0-logs/macmini/`。
4. **应用规则真机验证**：两种引擎下分别写入"`/usr/bin/curl` 始终拒绝"的应用规则后重新连接：curl 访问 www.apple.com 被拒绝（exit 35），python3 正常返回 HTTP 200。TUN 结果同时确认了 M0 结论：root 身份的系统扩展可通过 `pcblist_n` 识别 TCP 连接的进程。
5. **远程门禁**：`test_remote_arm64.sh fast` 通过（`outputs/test-evidence/remote-arm64-*-fast`）。

### 例外说明

1. **虚拟机矩阵改在物理真机执行**：按维护者决定，本版本不使用 Tart 虚拟机，6 维矩阵在 Mac mini 上执行（方法同 1.2.0、1.2.1）。为避免"先跑的引擎因另一扩展尚未升级而失败"，本轮先以透明代理连接一次完成扩展升级（报告保留为 `acceptance-prime.txt`，不计分），再依次验收 6 个组合。
2. **真机验证发现并修复的缺陷**：候选包 2026100503、2026100601 在真机上保存应用规则后两个扩展都无法启动（扩展对宿主编译的启动配置套用了导入校验；两个引擎入口仍拒绝进程规则）。修复后重新构建 2026100602，以上全部验证均基于 2026100602；前两个候选包未发布。
3. **互通门禁偶发失败一次**：一轮 sing-box 矩阵中 Trojan 的 UDP 回显在重传后内容不符，其余用例与其他 4 项通过；测试二进制与前后两轮完全相同（SHA-256 `ba161609…`），本次改动不涉及该路径，整轮重跑全部通过，判定为偶发。
4. **TUN 下 UDP 不识别来源应用**：引擎把 TUN 的 UDP 合并为单个数据报会话转发，无法逐流挂载来源应用；TUN 下 UDP 与 QUIC 显示"未知应用"、不受应用规则约束，界面与帮助中已说明。透明代理模式下 TCP 与 UDP 均可识别。

### 正式发布规范执行核验

1. 采用标准生产核心（Normal Core Variant），不含 QA 自动化标记，发布通道为 `stable`；
2. 主程序与两个网络扩展均为 Developer ID 签名与 Hardened Runtime；
3. 经 Apple 公证并完成票据装订（App + DMG）；
4. 安装包不含任何配置归档、测试服务器、私有凭据或订阅地址（`*.aetherroute`、`*.yaml`、`*.conf`），发布打包脚本核查仅含 `AetherRoute.app` 与 `Applications`，卷标为 `AetherRoute 1.3.0`。
