# v1.8.4 发布验收说明

2026-10-21，局域网共享代理修复与发布门禁加固，正式构建 2026102101（stable 通道，Normal Core）。

## 变更内容

- 局域网共享代理（`LANProxySession`）：握手跨多次读取累积，HTTP 与 SOCKS5 支持拆包与合包；只解码 HTTP 头部，二进制请求体完整转发；SOCKS5 只同意客户端提出的认证方式。
- 保留 TCP 半关闭：一个方向结束后以 60 秒空闲超时回收（有流量即续期），转发中出现终止状态给 5 秒宽限，对端不关闭的连接不再占满 256 个会话名额。
- 普通 HTTP 转发：请求行改写为 origin-form，去掉 `Proxy-Authorization`、`Proxy-Connection` 等逐跳字段与 URL 用户信息，强制 `Connection: close`，响应送达后结束会话；拒绝重复 `Host`、头部折行、`Content-Length` 与 `Transfer-Encoding` 并存。
- 发布流程：并行验收强制 300 秒 UI 档位与远程 ARM64 门禁；`package_release_dmg.sh` 只接受公证候选 DMG，并在签名前校验与该 DMG 绑定的物理机证据。

## 例外

### 1. VM 矩阵「透明代理 × 直连」首轮大上传超时，单独重跑通过

首轮记录为 `large upload: cut off (HTTP 200 after 2097152 of 2097152 bytes, 120.014535s)`：2 MiB 已完整上传且服务端返回 200，curl 在接收 httpbin 约 2.8 MB 回显时撞上 120 秒总超时。同轮 TUN × 直连为 111.9 秒，而经代理节点的规则与全局组合都在 8–10 秒；1.8.3 时直连为 36–38 秒。VM 直连出口当日下载约 550 KB/s。两个引擎在直连下同幅变慢、经代理组合正常，判定为 VM 直连出口慢，与本次改动（App 内局域网共享代理，不在该链路上）无关。

使用同一 QA 包单独重跑该组合（`outputs/vm-rerun-1.8.4-2026102101-transparent-direct`）：34 项检查 PASS 26、FAIL 0、SKIP 8，2 MiB 上传 64.4 秒送达。经维护者确认，以重跑结果认定通过。

### 2. Mac mini 未安装 Xcode，远程 ARM64 门禁跳过 5 项

Mac mini 的开发者目录为 `/Library/Developer/CommandLineTools`，`/Applications` 下没有 Xcode，门禁因此在真机上跳过：`test_product_build.sh`、`test_dmg_upgrade_rollback.sh`、`test_large_import_performance.sh`、SignedNEProbe 离线集成测试、SparkleAutoUpdateDebounce。这 5 项已在本机（完整 Xcode）`./scripts/test.sh` 中通过。经维护者确认本次接受；后续需在 Mac mini 安装 Xcode 并 `xcode-select -s` 后恢复真机覆盖。
