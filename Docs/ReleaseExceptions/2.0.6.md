# 2.0.6 验收与边界

发布构建：`2026110402`。Rust 核心提交 `8b94e0fc64fb95543fa99c74aa879893d2dc89d0`，针对本机统一日志（Unified Logging）发现的 P0–P1 问题完成修复并通过全量回归验证。

## 修复内容与测试先行（TDD）

1. **P0-1：Fake-IP 地址池保留、TLS SNI 反向映射自愈、非 A/AAAA 本地 NODATA 与 TUN DNS 并发去队头阻塞**
   - `FakeDns` 保留 `198.18.0.1`、`198.18.0.2`（`packetFlowDNSServers`）与 `198.18.0.255`，并在 `EncryptedFileStore` 加载时过滤历史残留的保留地址，确保 `198.18.0.2` 不会被分配给普通域名，且反向查找 `198.18.0.2` 不再递增 `FakeIpMappingMissing`。
   - 新增 `ClashResolver::restore_fake_ip_mapping`（`FakeDns::restore_if_unmapped`），当 `Dispatcher::dispatch_stream` 在 443 端口通过 TLS SNI 恢复出域名且目标属于未映射 Fake-IP 时，自动补齐 IP↔域名双向映射，使同一目标后续的 UDP/QUIC 443 数据报顺利通过 `reverse_lookup`。
   - Fake-IP 模式下对非 `A`/`AAAA` 查询（`HTTPS` type 65、`SVCB` type 64、`PTR`、`TXT` 等）直接本地返回空 `NoError`（NODATA），不再调用 `resolve_v4` 合成错误的 `RData::A` 记录。
   - `handle_inbound_datagram` 中劫持的 TUN UDP DNS 查询改为在有界 `JoinSet`（`MAX_CONCURRENT_TUN_DNS_QUERIES = 64`）上异步执行，消除上游慢 DNS 查询对 TUN UDP 数据面报文转发的队头阻塞。
2. **P0-2：休眠唤醒与物理网卡切换后的出站接口绑定自愈及重复重置消重**
   - Rust 引擎新增 `replace_failed_outbound_interface` / `get_outbound_interface_excluding`：当 `new_tcp_stream` 或 `new_udp_socket` 在已缓存的默认出站接口上触发 `must_bind_socket_on_interface` 失败时，自动排除失效接口索引、重新探测可用物理接口完成绑定并更新 `DEFAULT_OUTBOUND_INTERFACE`，消除休眠唤醒或热插拔瞬间的 `TcpBindFailed` 风暴。
   - `NetworkRecoveryCoordinator` 在首轮 `attempt 0`（如唤醒初期的 `physicalLinkChanged` / `pathChanged` / `wake`）进行中或刚在防抖窗口内完成时合并宿主发来的 `appMessage`，而在非唤醒恢复已失败首轮（`currentAttemptIndex >= 1`）处于长退避等待时仍立即抢占；`PacketTunnelProvider` 同步接入 `UplinkResetLedger`，物理上联签名未变时跳过冗余 `resetNetworkState`。
3. **P1-1 / P1-2 / P1-3：首选节点恢复探测连接池隔离、未达阈值健康探测日志降级、AppKit 进度指示器过渡与物理内存口径统一**
   - `TunnelManager+Failover.swift` 在 `checkFailoverRecovery` 探测首选节点前调用 `Self.refreshProbeSession()`，防止复用指向备用节点的连接池长连接。
   - `TunnelManager+Telemetry.swift` 将未达到 `automaticRouteFailureThreshold` 的单次 `stage=automaticRouteHealth failed consecutive=...` 降为 `.info`，仅在达到切换阈值时记录 `.error`。
   - `AetherProgressButtonLabel` 中的 `ProgressView` 移除 `.scale(scale: 0.6)` 缩放过渡，改为 `.transition(.opacity)`，消除 `AppKitProgressView` 在动画帧中触发 `min <= max` 约束报错。
   - `Manager::memory_usage()` 在 macOS 上改为通过 `proc_pid_rusage(getpid(), RUSAGE_INFO_V4, ...)` 读取 `ri_phys_footprint`，与活动监视器及 `DataPlaneSampler` 口径一致。
4. **TDD 红绿验证记录**
   - 6 项新增 Rust 单元测试在旧代码上全部失败（`0 passed; 6 failed`），修复后全部通过；
   - `scripts/test_recovery_and_subscription_compat_gate.sh` 与 `NetworkRecoveryCoordinatorTests` 新增断言在旧代码上失败（`FAILED: appMessage must coalesce into active physicalLinkChanged instead of superseding it`），修复后全部通过。
