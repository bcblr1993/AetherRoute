### 核心功能演进与缺陷修复：

1. **网络恢复多端点探测与容灾回退（`NetworkRecoveryHealthPolicy`）**：
   - 引入 Google 204、Cloudflare 204 及 Apple 测试服务等多候选探测 URL，规避单一端点受阻导致健康检查误判；
   - 探针超时或耗尽绝不误判为底层引擎崩溃，保留活跃路由与现有网络流，避免无谓断开无关的分流规则流量。

2. **流量增量健康判定（`hasReceivedTraffic`）**：
   - 恢复流程优先采样下载字节增量；若恢复期间已观测到真实数据包流动，立即判定数据通道健康通畅，无需重复等待网络请求探针。

3. **透明代理与生命周期防抖保护**：
   - 透明代理单次恢复周期内仅在首次尝试（`attempt == 0`）重置网络状态，避免后续轮次频繁重置掐断正在建立的长连接。

4. **连接状态清晰化与解耦（`.recovering` 状态）**：
   - 将网络恢复与初始连接准备解耦，引入独立的 `.recovering` 状态与中英文本地化展示（“隧道保持启用，正在等待网络恢复。你可以随时断开连接。”）；
   - 恢复期间持续保留会话连接时间（`connectedSince`），窗口与状态栏主菜单均始终保持“断开连接”操作可用。

5. **真机锁屏长连接连续性验证（`lock_continuity_probe.py`）**：
   - 严苛的单 TCP Keep-Alive 连接探针，禁用 HTTP 自动重连，实测锁屏与解锁全流程中连接不被中断、零断开重连、双进程零重启；
   - 显式区分模拟 QA 整机睡眠唤醒事件与屏幕锁屏，避免锁屏触发误恢复。
