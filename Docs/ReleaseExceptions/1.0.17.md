# v1.0.17 发布验收说明

2026-09-18，维护者在真实硬件设备（`chenxu@100.64.0.3` Apple Silicon Mac mini）重启实测中发现开机启动生效但未自动连接，提出修复与发布要求：

> chenxu@100.64.0.3 (Apple Silicon Mac mini) 只能开机启动 无法开启连接 我在这个上面重启了 2 次还是不行

### 核心功能演进与缺陷修复：

1. **开机自启动连接恢复门禁解耦（`TunnelManager`）**：
   - 彻底修复 `prepare()` 异步初始化执行期间 `isPreparing` 标志未复位导致 `canConnect` 门禁判定失败并跳过自动连接的根本缺陷；
   - 独立解耦 `canRestorePreviousConnection` 安全门禁，与 UI 防抖标识切分，并在扩展准备就绪后立即置 `isPreparing = false`；
   - 补充启动自动连接详尽的公开日志诊断信息。

2. **菜单栏资源占用优化（`AetherRouteApp`）**：
   - 引入 `MenuBarVisibilitySynchronizer` 动态感知菜单栏 Popover 弹出与遮挡状态；
   - 仅在菜单栏可视时激活高频遥测轮询，收起或隐藏时自动休眠，彻底消除后台 CPU 占用。

3. **TCP 半关闭连接看门狗（`TCPFlowStateMachine`）**：
   - 针对半关闭的透明代理 TCP 流增加 15 秒超时自动清理机制，防止悬空会话与描述符泄漏。

4. **TUN 模式批量发包性能优化（`CoreBridge`）**：
   - 引入线程安全出站缓冲区，将分散的网络包通过 `NEPacketTunnelFlow.writePackets` 批量提交，大幅降低内核系统调用开销。

### 物理真机与本地自动化回归通过证据：

1. **物理真实设备实机验证（`chenxu@100.64.0.3` Apple Silicon Mac mini）**：
   - 使用与系统扩展版本匹配的 Developer ID 签名纯生产 Candidate 安装测试；
   - 场景 1（冷启动自动重连）：应用退出时保持 intent=1，重新启动后 1 秒 Disconnected -> 2 秒 Connecting -> 3 秒 Connected，全静默秒级恢复成功（PASS）；
   - 场景 2（主动断开保持断开）：在退出前标记 intent=0，重新启动后 8 秒维持 Disconnected 状态（PASS）；
   - 场景 3（状态复原）：重新标记 intent=1 启动，隧道恢复 Connected（PASS）。
   - **结论**：真实 Mac mini 硬件环境下自动恢复连接 100% 验证通过。

2. **本地回归测试与静态核验**：
   - 本地构建与自动化测试矩阵（`./scripts/test_product_build.sh`，104+ 测试）全绿通过；

### 正式发布规范执行核验：

1. 采用标准生产核心（Normal Core Variant），完全剥离 QA 自动化测试标记；
2. 主程序（`com.aetherroute.desktop`）及网络扩展（`com.aetherroute.desktop.tunnel`、`com.aetherroute.desktop.transparent-proxy`）均采用 Developer ID 签名与 Hardened Runtime；
3. 通过 Apple Notarization 官方公证（Accepted）并完成票据装订（Stapled）；
4. Sparkle 自动更新清单采用官方专用 Ed25519 密钥签名并经反向验签断言通过；
5. 生成完整 SHA256SUMS 校验清单并发布官网与 GitHub。
