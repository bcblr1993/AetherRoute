# v1.5.0 发布验收说明

2026-10-10，功能版本，正式构建 2026101002。首次启动授权改为三页引导式设计（隐私承诺、网络权限、准备就绪）；应用内更新说明由官网 Appcast 生成分组样式。

## 变更内容

- **共享引导布局**（`OnboardingComponents.swift`）：插图、标题与说明、卡片行、脚注，主按钮与页码固定在底部操作栏（macOS 26 起为 `safeAreaBar` + 柔和滚动边缘，更早版本为材质背景的 `safeAreaInset`）。最小窗口下页面在操作栏下方滚动，主按钮不会被挤出窗口。
- **隐私承诺页**（第 1 页）：四项承诺加数据流向一行，主按钮「同意并继续」。设置中的隐私摘要与表单版保持原样。
- **网络权限页**（第 2 页）：两个引擎各一行，状态映射为等待、允许、打开系统设置、已授权（绿色对勾）、需要重启、重试或不可用。TunnelManager 授权逻辑未改。权限被撤销后弹出的重新授权表单复用该页，不显示页码与最后一页。
- **准备就绪页**（第 3 页）：汇总隐私承诺与两个引擎状态，「开始使用 AetherRoute」调用 `finishNetworkSetup()` 进入主界面。
- **设计规范**：新增 4 个视觉令牌（卡片宽度 520、分隔线缩进、按钮宽度 240、插图高度 128），图标尺寸只用既有五档；新增 7 条中文本地化文案。
- **官网 Appcast**（bcblr1993/aethernative-site `539695a`，已上线）：更新说明按「新功能 / 修复 / 优化」分组并附内联样式，用户在更新到 1.5.0 时即可看到。

## 例外说明

1. **VM 环境**：首轮完整 UI 测试因 VM 磁盘写满（`No space left on device`）及其他项目遗留的 5 个「AetherTerm 无法打开」系统弹窗遮挡窗口，25 项失败；随后 VM 图形会话卡死（App 主线程阻塞在 WindowServer 调用 `SLSWindowServerClientSpaceCopyName`）。经维护者同意清理其他项目的遗留文件、重启并登录 VM 后，按批次重跑完整 UI 测试（每批结束删除结果包），结果见第 6 项。
2. **UI 测试调整**：新增的 `testPrivacyPageKeepsConsentInReachAcrossLanguagesAndAppearances` 原先断言「同意并继续」的 `isHittable`。最小窗口下页面在底部操作栏下方滚动，XCUITest 的命中检测返回按钮后方的内容行，因此该断言恒为 false，但真实点击落在按钮上（既有的 `testPrivacyDisclosureBlocksNetworkFeaturesUntilAccepted` 同尺寸下以坐标点击通过）。改为与之相同的坐标点击并断言进入概览。该改动只涉及 UI 测试文件，发生在公证候选包构建之后；候选包 `source-manifest.txt` 中 `Tests/AetherRouteUITests/AetherRouteUITests.swift` 的哈希因此与发布提交不同，应用与扩展的源码一致。
3. **Mac mini 门禁网络**：局域网 `192.168.50.226` 不可达，改经 Tailscale `100.64.0.3` 运行。
4. **跳过的 UI 用例**：`testSignedNetworkExtensionConnectDisconnectLifecycle`、`testBilingualNavigationResponsiveness`、`testCaptureUIReviewMatrix` 需要显式环境变量才会运行，与历次发布一致。

## 正式发布规范执行核验

1. 采用标准生产核心（Normal Core Variant），不含 QA 自动化标记，发布通道为 `stable`；
2. 主程序与两个网络扩展均为 Developer ID 签名与 Hardened Runtime；
3. 经 Apple 公证并完成票据装订（App + DMG）；
4. 安装包不含任何配置归档、测试服务器、私有凭据或订阅地址（`*.aetherroute`、`*.yaml`、`*.conf`），发布打包脚本核查仅含 `AetherRoute.app` 与 `Applications`，卷标为 `AetherRoute 1.5.0`。
