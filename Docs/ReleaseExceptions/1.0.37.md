# v1.0.37 发布验收说明

2026-09-30，新增首次启动网络权限引导，并根据 1.0.36 真实数据走查修正界面一致性问题。网络引擎、协议实现与两个网络扩展的代码与 1.0.36 相同。

### 新增

1. **首次启动网络权限引导**：隐私说明之后新增"设置网络权限"一步，同时提交透明代理与 TUN 两个系统扩展请求（在"系统设置 › 通用 › 登录项与扩展 › 网络扩展"中一次打开两个开关），再依次保存两份网络配置（macOS 逐个询问"允许"）；两个引擎都就绪后才进入主界面，之后连接或切换引擎不再被系统弹窗打断。
   - 配置以未启用状态保存，创建 TUN 配置不会关闭其他 App 的 VPN，连接时自动启用；
   - 被组织策略禁止的引擎不会把用户挡在门外，可用另一引擎继续；
   - 老用户升级不受影响；中途退出，下次启动继续引导；菜单栏、全局快捷键、URL 导入在引导完成前不能发起连接；
   - 权限被收回时，概览恢复卡片提供"重新设置权限"，打开同一页面。
2. **配置页**：只有一个配置时显示"添加更多配置"（订阅 / 导入 / 添加节点）；3 个及以上配置才显示搜索框。

### 改进

1. **设置窗口**：四个分页统一为同一分组表单（宽度、边距、分区标题一致）；"隐私与诊断""关于"改为表单分区；侧栏与主窗口一致（正文字号、灰色选中），不再是大号粗体加蓝色整条选中。
2. **时长格式统一**：概览、连接会话条、连接表格统一为最大两个单位的缩写格式（"2小时11分钟" / "49分钟2秒"）。
3. **延迟配色**：绿色 ≤200 ms、橙色 ≤500 ms（原 120 / 260 ms），跨境节点不再全部显示红色。
4. **菜单栏新版本标签**改为实心强调色 + 白字，深色下清晰可见。
5. **分区标题与状态胶囊**使用统一组件；规则页不再在卡片内重复"自定义分流规则"。
6. **概览波形**：主窗口可见时任意页面都保留 10 秒一次的流量采样，切回概览立即显示波形。

### 修复

1. **正式版"关于"显示为测试版本**：正式 DMG 由写死 `beta` 通道的公证候选包重新打包（1.0.34~1.0.36 均受影响）。现在发布候选包以 `AETHERROUTE_CANDIDATE_CHANNEL=stable` 构建，`package_release_dmg.sh` 拒绝非 stable 通道。
2. **DNS 页**"解析模式"控件溢出卡片；**配置、DNS 页**宽度窄于其他页面。
3. **连接表**只有目标列铺底色；**绕过规则**输入框示例文字显示为行标签。

### 验证结论

1. **本地回归**：`test_network_switch_gate.py`、`Tests/EngineReconnect/run.sh`、`Tests/RuntimeEnvironment/run.sh`、`./scripts/test.sh` 全部通过；单元测试 472 个全部通过。
2. **首次启动引导实测（Tart 虚拟机 `macos27`）**：卸载两个系统扩展并清除网络配置与偏好后安装 1.0.37，引导同时提交两个扩展请求，在系统设置中一次开启后两份配置创建完成，引导结束并正常进入主界面。
3. **老用户升级（物理 Mac mini）**：1.0.36 升级到 1.0.37 未进入引导（`existing=true`），自动恢复连接；发布通道为 `stable`。
4. **Tart 虚拟机矩阵（`macos27`，构建 2026093005）**：6 个组合全部通过，含大请求上传、空闲 Keep-Alive 复用与透明代理 SNI 恢复检查；测试后已清理虚拟机临时文件。
5. **物理真机（Apple Silicon Mac mini）**：使用公证候选包实测——TUN 模式 2 MiB 上传 6.0 秒、6 MiB 7.0 秒，空闲 Keep-Alive 复用通过；透明代理模式 2 MiB 3.7 秒、6 MiB 6.4 秒，空闲 Keep-Alive 复用与 SNI 恢复通过；远程回归门禁 `test_remote_arm64.sh fast` 通过，门禁前后系统代理、DNS、默认路由与网卡状态一致。

### 例外说明

- **虚拟机矩阵 TUN 组合重跑**：首轮 TUN 三组判定为未连接，但同一检查中 IPv4 默认路由已在 `utun4`（隧道实际已建立）。原因是为测试首次引导手动重置虚拟机时，系统网络偏好中残留了一个同名"AetherRoute"服务，矩阵按名称查询连接状态读到的是这个残留服务，新配置被系统自动命名为"AetherRoute 2"。清除残留服务后重跑 TUN 三组全部通过；透明代理三组首轮即通过。此问题只由手动删除系统文件引起，正常安装、卸载不会出现。

### 正式发布规范执行核验

1. 采用标准生产核心（Normal Core Variant），不含 QA 自动化标记，发布通道为 `stable`；

3. 经 Apple 公证并完成票据装订（App + DMG）；
4. Sparkle 更新清单使用 Ed25519 密钥签名并通过验签；
5. 磁盘镜像不含测试说明文件，卷标为 `AetherRoute 1.0.37`。
