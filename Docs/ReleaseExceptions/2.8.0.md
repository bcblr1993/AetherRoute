# 2.8.0 验收与边界

发布构建：`2026110804`。Rust 核心提交 `df30585e7265e5dea2149e29fbc94e1fa5888f57`（`df30585`），重点完成全功能模块端到端代码审查（Code Review）与运行时日志联合审计后的性能、稳定性、并发预算与规则筛选一致性优化。

## 核心特性与优化

1. **零分配连接出站分类器与 2,000 连接表格快速路径（`ConnectionOutletClassifier`、`ConnectionTableItem.swift`、`ProxyNodeStatus.swift`、`ConnectionsPageView.swift`）**
   - 新增 `ConnectionOutletClassifier`（`classify(_:)`、`leafOutletName(_:)`、`counts(for:)`），采用切片与反向箭头区间定位替代 `components(separatedBy:)` 数组分配及全串 `.uppercased()`，消除每轮渲染在 2,000 条连接上的数千次临时数组/字符串分配。
   - `ConnectionTableItem.identify(_:)` 预分配哈希表容量（`reserveCapacity`）；`ConnectionsView.connectionRows` 在未开启筛选/搜索时直接走快速路径，跳过无意义的 2,000 次 `SourceAppDirectory.presentation(for:)` 查询；单元格缓存单次 `outlet` 计算结果。
   - **实测效果**：在 `large` 夹具（2,000 条连接）下，`main.connections` 页面切页延迟从 `p50 = 115.4 ms / p95 = 124.8 ms / max = 128.6 ms` 降至 **`p50 = 106.3 ms / p95 = 118.1 ms / max = 121.1 ms`**；`showcase` 档位最大切页延迟从 `155.4 ms` 降至 **`129.1 ms`**（降低 `26.3 ms`）。

2. **策略组重复节点名防崩溃与 500 节点 `O(1)` 字典预索引（`ProxyPageNodeOrder.swift`、`ProxiesPageView.swift`）**
   - 新增 `ProxyPageNodeOrder.uniqueMembersPreservingOrder(_:)`，在保留订阅原始顺序的前提下对策略组内重复节点名去重，并使用 `Dictionary(..., uniquingKeysWith: { first, _ in first })`，彻底消除第三方订阅存在同名节点时 `Dictionary(uniqueKeysWithValues:)` 触发运行时崩溃的隐患。
   - 在 `ActiveProxyGroupView.memberRows` 中预构建 `statusByMember`、`typeByMember`、`groupNameSet` 与 `chainedByName` 哈希表，将 500 节点列表渲染从 `O(N^2)` 线性扫描降为 `O(N)`。
   - **实测效果**：在 `large` 夹具（500 节点）下，`main.proxies` 页面切页延迟从 `p50 = 69.7 ms / p95 = 80.8 ms` 降至 **`p50 = 65.9 ms / p95 = 77.9 ms`**。

3. **规则页 `REJECT-DROP` 筛选对齐与万级规则快速路径（`RulesPageView.swift`）**
   - 修复 `RuleActionFilter.accepts(_:)` 中 `.reject` 未包含 `"REJECT-DROP"` 且 `.proxy` 误包含 `"REJECT-DROP"` 的问题，使其与 `ProfileConfigurationSummary.rejectRuleCount` 及 `RuleTargetLabel` 完全一致。
   - 在 `selectedAction == .all && searchText.isEmpty` 默认状态下跳过全量 `.filter` 遍历与每次迭代的字符串小写转换。
   - **实测效果**：在 `large` 夹具（10,000 条规则）下，`main.rules` 页面切页延迟从 `p50 = 77.1 ms / p95 = 89.3 ms` 降至 **`p50 = 72.0 ms / p95 = 87.6 ms`**。

4. **透明代理上游域名并发解析与总超时预算防卡死（`TransparentProxyUpstreamEndpointResolver.swift`）**
   - `TransparentProxyUpstreamEndpointResolver.resolve(profileYAML:maxResolutionDurationSeconds:hostResolver:)` 新增按主机名（大小写不敏感）去重与并发 DNS 解析，并引入默认 `3.5s` 总预算上限。当订阅中包含死域名或响应超时的权威 DNS 时，不再串行阻塞 `TransparentProxyProvider.startProxy` 触发 25 秒连接看门狗超时，而是在预算内保留所有已解析成功的上游排除规则并正常启动。

5. **DNS 页网络诊断医生真实 HTTP 连通性探测与过期规则集统计（`NetworkDiagnosticDoctor.swift`、`DNSPageView.swift`）**
   - 新增 `NetworkDiagnosticDoctor.countStaleRuleProviders(_:now:)` 与 `NetworkDiagnosticDoctor.probeHTTPConnectivity(url:timeoutSeconds:)`，使 DNS 页「网络诊断检查」在真实运行环境下并发探测国内直连（`captive.apple.com`）与代理出站（`www.google.com/generate_204`）HTTP 往返延迟，并准确统计自定义远程规则集过期数量。

6. **运行时证据采集 LaunchServices `-600` 竞态修复（`scripts/collect_physical_runtime_pair.sh`）**
   - 使用带重试退避的 `open -n -a /Applications/AetherRoute.app` 替代紧跟进程退出后的直接 `open -a`，彻底消除 LaunchServices 偶发返回 `-600`（`procNotFound`）日志告警。
