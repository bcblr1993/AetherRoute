# v1.4.1 发布验收说明

2026-10-09，修复版本，正式构建 2026100902。包含 1.4.0 发布后审查发现并修复的问题。

## 修复内容

- 透明代理：延迟测试此前在整个测试期间持有 `admissionLock`，期间整机所有新的 TCP/UDP 连接都要排队。升级到 1.4.0 后的首次连接出现约 21 秒停顿，并伴随两条主机消息超时和 29 个 UDP 流失败。现在控制调用改用独立的 `controlLock` 串行（与 TUN 一致）；停止时等进行中的控制调用结束后再关闭引擎。
- 启动恢复连接：先等待可用网络和每次尝试的实际结果，总预算 120 秒，用户主动断开优先。
- 流量统计：账本暂时不可读时不再被空账本覆盖，读取成功后合并期间的样本；永久损坏时改名备份。断开或退出前补采一次样本，期间界面立即显示「断开中」并拒绝新的连接请求。
- 节点链接导入超限时给出具体限制；日志查看器每次更新只过滤一次；弹窗容器保留子控件无障碍标识。

## 例外说明

1. **5 项既有 UI 失败**：自 v1.3.3 起在 macOS 27 上就已失败，与本次改动无关，另开任务排查：
   - `testRulesPassAccessibilityAuditInLightAndDark`：规则页有元素缺少可点击的无障碍动作；
   - `testConnectionsPassAccessibilityAuditInLightAndDark`、`testExpandedTextRemainsUsableAcrossChinesePrimaryPages`：列表行数为 3，预期为 2；
   - `testExpandedTextRemainsUsableAcrossEnglishPrimaryPages`：英文长文案在最小窗口下超出 5pt（806 > 801）；
   - `testTUNLocalProxyIsExplicitLoopbackOnlyAndCopyOnly`：TUN 本地代理设置页的一项断言。
2. **测速期间连接耗时未做真机实测**：Mac mini 处于登录窗口，AetherRoute 无窗口运行，没有不经界面就能触发测速的入口。该修复以单元测试为准，测试用人为阻塞的测速证明新连接仍立即接入。1.4.0 首次连接时那约 21 秒停顿的日志分析见本说明「修复内容」。
3. **VM 矩阵重跑**：首轮 VM 矩阵使用的 QA 候选包早于 `cdb0120`，已用包含它的候选包重跑；首轮结果保存在 `outputs/vm-acceptance-1.4.1-2026100902-precdb0120/`。第二轮因 VM 中残留首轮候选包的 TUN 扩展进程，矩阵在建立基线时拒绝打分。重启 VM 后仍运行首轮的扩展二进制：两个候选包构建号同为 2026100902，系统扩展守护进程不替换同版本扩展。因此用同一份源码以构建号 2026100903 重建 QA 候选包，供 VM 矩阵使用；除 QA 版固有的诊断核心与许可证清单外，源码清单与正式包 2026100902 完全一致。正式发布包仍为 2026100902，已在 Mac mini 上通过远程门禁与真机验证。
4. **Mac mini 门禁网络**：局域网 `192.168.50.226` 当时不可达，改经 Tailscale `100.64.0.3` 运行。
