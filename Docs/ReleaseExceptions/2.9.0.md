# 2.9.0 验收与边界

发布构建：`2026110805`。Rust 核心提交 `df30585e7265e5dea2149e29fbc94e1fa5888f57`（`df30585`），重点完成全功能模块与全部子功能的逐文件深度代码审查（Code Review）与运行时日志联合审计后的 10 项稳定性修复、内存零分配优化与 UI 切页延迟优化。

## 核心修复与优化

1. **透明代理客户端发包并半关闭后首包下行 `.closed` 误报 `outcome=failed` 修复（`TCPFlowStateMachine.swift`）**
   - **日志根因**：在 `vm-acceptance/transparent-rule.txt` 与 `transparent-global.txt` 中捕获到 `stage=tcpTermination ... trigger=flowWrite outcome=failed error=closed ... firstEOF=flowRead flowReadBytes=1545 bridgeWrittenBytes=1545 bridgeReadBytes=4591 flowWrittenBytes=0 pendingFlowWriteBytes=4591`。当本地客户端发送完整请求（`bridgeWrittenBytes = 1545`）并主动关闭连接（`flowInputEnded == true`）后，服务端返回的首包响应（`flowWrittenBytes == 0`）写入已关闭的本地流触发 `.closed` 时，原条件仅检查 `flowWrittenBytes > 0`，导致正常短连接关闭被误判为 `outcome=failed`（触发 `sessionsFailed` 计数与 Error 级日志）。
   - **TDD 修复**：在 `completeFlowWrite` 与 `completeBridgeWrite` 中支持 `flowWrittenBytes > 0 || bridgeWrittenBytes > 0` 且对端输入已结束时走 `finishAfterPeerClosedPostEOF()` 正常收敛，同时保留零字节连接异常关闭的 `outcome=failed` 诊断语义。

2. **被动节点快照刷新消除双次全窗口重排与冗余磁盘写入（`TunnelManager+ProxySelection.swift`、`TunnelManager.swift`）**
   - 将 `Overview` 与 `Proxies` 页面出现时的只读快照刷新（`requestedMember == nil`）移入非 `@Published` 的 `proxySnapshotRefreshRequests` 集合，离线且已有缓存快照时直接跳过后台磁盘读取，仅在实际选择发生变更时才写回 `ProxySelectionStore`，消除了每次切到概览/节点页时触发两次 `TunnelManager.objectWillChange` 全窗口重排与按钮瞬时禁用的问题。

3. **国际化 ICU `DateComponentsFormatter` / `Locale` / 地区名缓存（`AppLanguageController.swift`、`ProxiesPageView.swift`）**
   - 在 `AppLocalization` 内缓存当前 `Locale`、秒级/分钟级双 `DateComponentsFormatter` 实例与地区名映射表（切换语言时原子失效重建），并将 `ProxiesPageView.swift` 中 4 处绕过应用内语言设置的 `.formatted(date:time:)` 统一收敛至 `AppLocalization.date(_:date:time:)`，消除了连接页每行 `ConnectionDurationCell` 及节点页每行渲染时重复创建 ICU 格式化器的高额开销。

4. **节点页单次 `memberRows` 计算、`NodeRegion` 静态缓存与链式代理快速路径（`ProxiesPageView.swift`、`NodeRegion.swift`、`TunnelManager+ProfileOverrides.swift`）**
   - `ActiveProxyGroupView.body` 单次计算 `allMembers` 与 `rows = computeMemberRows(from: allMembers)`（消除每次渲染重复执行 3 次 `memberRows` 与 5 次 `members` 的开销）。
   - `NodeRegion.resolve(from:)` 引入 2,048 条上限的线程安全缓存与纯 ASCII 标量分词、切片 `elementsEqual` 匹配；`NodeRegion.filterMembers` 在无搜索词且未隐藏超时节点时 `O(1)` 直接返回。
   - `TunnelManager.standaloneChainedProxyGroupName` 在无独立链式代理覆写时直接返回 `nil`，避免每次渲染 `ProxiesView` 时重跑完整 YAML `ProfileOverrideCompiler`。

5. **自动策略组出口解析去重与 `O(L)` 单遍聚合（`GroupLeafResolver.swift`、`TunnelManager+Telemetry.swift`）**
   - 新增 `GroupLeafResolver.leaves(forGroups:chains:)`，先对 2,000 条连接中重复的 `proxyChain` 字符串去重再拆分跳数，并以单遍 `O(L)` 最大值扫描替代原 `O(L^2)` 的 `firstSeen.firstIndex(of:)` 比较；无自动策略组时完全跳过 `snapshot.connections.map(\.proxyChain)` 数组分配。

6. **独立自定义 `rule-providers` 的 iCloud 实时同步监听补齐（`TunnelManager.swift`）**
   - 新增 `cloudSyncRuleProvidersObserver` 监听 `.aetherRouteCloudSyncDidUpdateRuleProviders`，确保仅修改远程规则集并经 iCloud 同步时，本地立即重新加载规则集、刷新 `activeProfileSummary` 并热重载运行中的隧道规则。

7. **多节点原生配置重命名节点时自动同步兄弟节点 `dialerProxy` 引用（`AetherNode.swift`、`NativeProfileEditorView.swift`）**
   - 新增 `AetherNode.replacing(_:in:)` 并在 `NativeProfileEditorSheet.replace(_:)` 中调用，重命名前置节点时自动更新引用该节点的兄弟节点 `dialerProxy` 字段，同时在 `footer` 中单次求值 `validationMessage`。

8. **规则页空自定义规则 `O(1)` 短路与应用图标/Bundle ID 缓存（`TunnelManager+CustomRules.swift`、`SourceAppDirectory.swift`、`ApplicationRulesSection.swift`）**
   - 在 `destinationRule(kind:value:)` 与 `applicationRule(bundleIdentifier:bundlePath:)` 顶部增加 `guard !customRules.isEmpty else { return nil }`，避免默认无自定义规则时每行 `RuleRow` 构造临时 `CustomRule` 与 `UUID`。
   - `SourceAppDirectory` 缓存应用 `Bundle(path:)?.bundleIdentifier` 与 `ApplicationRuleRow` 图标，`ApplicationRulesSection.recentApps` 跳过无源应用标识的连接。

9. **连接页 2,000 条连接快照级缓存与移除重复空状态视图（`TunnelManager.swift`、`ConnectionsPageView.swift`）**
   - 在 `NetworkTelemetryViewModel` 上按当前 `snapshot` 缓存 `identifiedSnapshotConnections()`、`trafficSortedSnapshotConnections()` 与 `snapshotOutletCounts()`，使切页到「连接」页时直接复用已排序数组，不再重复对 2,000 条连接执行字典哈希、排序与分类统计；移除 `connectionList` 内部与外层 `.overlay` 重复的 `ContentUnavailableView.search`，并在 `ConnectionDestinationCell` 中单次求值 `isRejected`。

10. **配置页节点数同步读取缓存与固定宽度进度条去 `GeometryReader`（`ProfilesPageView.swift`、`ContentView.swift`）**
    - `ManagedProfileRow` 渲染时直接同步读取 `ProfileNodeCountCache.counts[key]` 并以轻量 `Key` 作为 `.task(id:)` 标识，消除每次切到「配置」页时的二次重绘；移除 `SubscriptionUsageLine`（96 pt）与 `LiveMemoryTotalFooter`（72 pt）中固定宽度下的冗余 `GeometryReader`。
