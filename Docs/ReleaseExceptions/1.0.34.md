# v1.0.34 发布验收说明

2026-09-29，修复通过 VLESS Vision 节点上传大请求时连接被断开的问题（Claude Desktop / Claude Code 长会话 `ECONNRESET` 的根因），新增大请求上传发版门禁。

### 修复

1. **VLESS Vision 大上传断连（`Core/Engine` VLESS Vision）**：
   - Vision 帧头用 2 字节记录内容长度；客户端写入快于节点上行时，引擎一次交给出站 64 KiB（65536 字节，比 2 字节上限多 1），长度被截断为 0 而数据照常发出，服务器解析错位后约 2 秒断开连接；
   - 表现为超过约 1 MB 的上传失败，限速上传和 Clash Verge 走同一节点均正常。Claude 长会话每次请求都携带完整上下文，因此在 AetherRoute 下每次重试都 `ECONNRESET`，切换 Verge 即恢复；
   - 现在每个 Vision 帧最多 8 KiB（与 Xray 客户端一致），其余数据由调用方继续写入。
2. **Hysteria2 不受影响**：其数据直接写入 QUIC 流。在未修复的 1.0.33 上经同一服务器实测，2 MiB 与 6 MiB 上传均在 3.6–6.3 秒内完整送达。

### 新增

3. **大请求上传门禁（`scripts/test_large_upload.sh`）**：经代理向 `httpbin.org/post` 上传 2 MiB 随机数据，必须 HTTP 200 且完整送达；纳入虚拟机矩阵全部组合与物理真机两种模式。该门禁在 1.0.33 上失败（1.9 秒被切断），经 Verge 走同一节点通过。

---

### 验证结论

1. **引擎**：343 个单元测试通过，其中新增的 2 个 Vision 测试在修复前失败；运行时验收回归 43 个用例通过。
2. **本地回归**：`test_network_switch_gate.py`、`Tests/EngineReconnect/run.sh`、`Tests/RuntimeEnvironment/run.sh`、`./scripts/test.sh` 全部通过。
3. **Tart 虚拟机矩阵（`macos27`）**：6 个组合首轮全部通过（经 VLESS 节点的大上传 7–11 秒；两个 direct 组合不经节点，经虚拟机直连 92–118 秒），含大请求上传、空闲 Keep-Alive 复用与透明代理 SNI 恢复检查；测试后已清理虚拟机临时文件。
4. **物理真机（Apple Silicon Mac mini）**：使用公证候选包经 VLESS Vision 节点实测——TUN 模式 2 MiB 4.0 秒、6 MiB 6.2 秒送达，空闲复用通过；透明代理模式 2 MiB 3.6 秒、6 MiB 6.1 秒送达，空闲复用与 SNI 恢复通过。
5. **发布例外**：`test_remote_arm64.sh fast` 全部测试套件跑完，但因运行期间为真机检查切换了 TUN / 透明代理模式，结束时的网络状态核对未通过；应维护者要求跳过重跑，本版真机证据以上述实测为准。
