# 2.9.3 验收与边界

发布构建：`2026111101`。Rust 核心提交 `674bc7a4cf5b90de49ad328b351761b50b453117`（`674bc7a`），重点修复 Hysteria2 节点连接运行 `apernet/hysteria` v2.13.0（`quic-go` v0.63.1）的服务端时全部「超时」（`H3_CLOSED_CRITICAL_STREAM`）的问题，并修正 Brutal 下行带宽协商、纯 IP 节点缺省 SNI 回退与端口跳跃网卡绑定。

## 核心修复与优化

1. **HTTP/3 关键流被提前关闭导致服务端回送 `0x0104 H3_CLOSED_CRITICAL_STREAM`（`Core/Engine/clash-lib/src/proxy/hysteria2/outbound/mod.rs`）**
   - **根因**：`Handler::auth()` 用 `let (_, mut sender) = h3::client::builder().build(h3_conn).await?` 建立 HTTP/3 客户端，立即丢弃了 `h3::client::Connection`。该对象持有 HTTP/3 单向 Control 流（`0x00`）与 QPACK 编解码流（`0x02`/`0x03`），被丢弃后客户端在 `/auth` 完成后立刻对这些关键流发送 `FIN`。遵循 RFC 9114 §6.2.1 的服务端（`apernet/hysteria` v2.13.0 / `quic-go` v0.63.1）随即以 `0x0104 H3_CLOSED_CRITICAL_STREAM` 关闭整条 QUIC 连接。服务端日志为 `client connected {"tx": 0}`，同一毫秒内 `client disconnected {"error": "accepting stream failed: H3_CLOSED_CRITICAL_STREAM (local)"}`，App 中节点延迟显示「超时」。
   - **TDD 修复**：新增 `H3ClientGuard`，同时持有 `h3::client::Connection` 与 `SendRequest`，存入 `Handler.guard`，与 `quinn::Connection` 同生命周期；连接断开重建、网络代数切换与 `shutdown()` 时先关闭 QUIC 连接再释放 `guard`。

2. **`Hysteria-CC-RX` 下行带宽协商（同文件及 `clash-lib/src/proxy/converters/hysteria2.rs`）**
   - **根因**：`auth()` 硬编码发送 `Hysteria-CC-RX: 0`；转换器用 `up.zip(down)`，只配置 `down` 时下行带宽被静默丢弃。
   - **TDD 修复**：按配置的 `down` 以字节每秒发送（`Mbps × 125,000`，如 `32 Mbps` → `4000000`，未配置为 `0`）；`up`/`down` 独立保留。

3. **纯 IP 节点缺省 `sni`（引擎与 `Sources/AetherRouteKit/SubscriptionPayloadNormalizer.swift`）**
   - **根因**：引擎在 `sni` 缺省时向 `quinn::Endpoint::connect` 传入空串（`invalid server name: ""`）；Swift 分享链接规范化 `parseHysteria2` 在无 `sni`/`peer` 时生成空 `sni`。
   - **TDD 修复**：引擎回退为节点主机名或 IP 字面量（IPv6 去括号）；Swift 规范化在 `sni`/`servername`/`server-name`/`peer` 缺省或为空时回退为链接主机，与 `AetherNodeURIParser` 一致。

4. **端口跳跃未绑定出口网卡（`clash-lib/src/proxy/hysteria2/udp_hop.rs`）**
   - **根因**：`UdpHop` 使用裸 `std::net::UdpSocket::bind("0.0.0.0:0")`，绕过其它出站统一使用的物理网卡绑定（`IP_BOUND_IF` / `SO_BINDTODEVICE` / `so_mark`），且不支持 IPv6 服务端。
   - **TDD 修复**：初始与跳跃套接字统一经 `new_udp_socket(iface, ..., server)` 创建。
