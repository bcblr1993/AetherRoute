# v1.1.1 发布验收说明

2026-10-02，设置与所有表单弹窗改为和主窗口一致的液态玻璃设计，隐私页重写，菜单栏面板底栏重排，并修复英文界面溢出与若干辅助功能问题。网络引擎、协议实现与两个网络扩展的代码与 1.1.0 相同（`Sources/AetherRoutePacketTunnel`、`Sources/AetherRouteTransparentProxy*`、`Sources/AetherRouteKit`、`Core` 无改动）。

### 验证结论

1. **本地回归**：`test_network_switch_gate.py`、`Tests/EngineReconnect/run.sh`、`Tests/RuntimeEnvironment/run.sh`、`./scripts/test.sh` 全部通过。
2. **Mac mini 全套 UI 测试**：42/42 通过（非 Retina 显示器、深色外观），补齐 1.1.0 未复跑的例外。
3. **物理真机（Apple Silicon Mac mini）**：使用公证候选包、两个系统扩展均已升级为 2026100201——TUN 模式 2 MiB 上传 4.6 秒、6 MiB 5.5 秒，空闲 Keep-Alive 复用通过；透明代理模式 2 MiB 3.5 秒、6 MiB 7.3 秒，空闲 Keep-Alive 复用与 SNI 恢复通过；远程回归门禁 `test_remote_arm64.sh fast` 通过。
4. **Tart 虚拟机矩阵（`macos27`，构建 2026100201）**：6 个组合的强制门禁项（空闲 Keep-Alive 复用、2 MiB 大上传 3.5–4.2 秒、透明代理 SNI 恢复）两轮全部通过；测试后已清理虚拟机临时文件。

### 例外说明

- **虚拟机矩阵连通性探测间歇超时**：两轮矩阵分别有 5 项与 4 项失败，均为外网连通性探测超时（强制门户探测、Anthropic/国内站点可达性、出口地址、IPv6 探测、`tun/direct` 本地 HTTP 代理返回 000），且两轮失败的组合与检查项互不相同（`transparent/rule` 的 IPv6 探测两轮都超时，1.1.0 同组合 1.3 秒通过）；第一轮透明代理的强制门户探测耗时 5–18 秒（正常 0.2 秒）。连 `direct` 路由组合（不经代理）也出现超时，说明是虚拟机出口不稳定：虚拟机流量经本机 NAT，再经本机自身的 AetherRoute TUN 与 Tailscale 出网。本版本网络引擎与扩展代码与 1.1.0 相同，物理真机双模式全部通过，因此未阻断发布。
- **首轮真机检查无效、已重做**：Mac mini 上一个 1.1.0 应用进程（2026-10-01 23:56 启动）忽略了退出请求（`quitAppleEvent ignored reason=pending`），导致首轮检查实际运行的是旧进程与 1.1.0 扩展，透明代理模式未生效、SNI 恢复失败。强制结束旧进程后重做，确认运行的是 1.1.1 进程与 2026100201 扩展，全部通过；新版本应用可正常退出。旧进程为何停在"等待退出"状态无法从已轮转的日志确认，另行跟进。
- **QA 候选包重建两次**：本机连接的 iPhone 使 Xcode CoreDevice 反复建立/拆除 `utun7` 隧道，触发构建脚本"构建期间网络状态不得变化"的检查；未放宽检查，待隧道稳定后第三次构建通过。

### 正式发布规范执行核验

1. 采用标准生产核心（Normal Core Variant），不含 QA 自动化标记，发布通道为 `stable`；
2. 主程序与两个网络扩展均为 Developer ID 签名与 Hardened Runtime；
3. 经 Apple 公证并完成票据装订（App + DMG）；
4. 安装包不含任何配置归档、测试服务器、私有凭据或订阅地址（`*.aetherroute`、`*.yaml`、`*.conf`），已挂载 DMG 逐项核查，仅含 `AetherRoute.app` 与 `Applications`。
