# v1.7.2 发布验收说明

2026-10-13，稳定性与可观测性增强版本，正式构建 2026101301。本版本针对控制面跨进程失联、UDP 短连接对端重置产生告警噪点、宿主关键诊断信息未持久化及流量统计字段兼容性进行全方位加固与闭环修复，确保客户端与系统扩展在各种异常网络波动与长时间高负载下均能自愈且零干扰。分析与实施记录见 `Docs/Plan-1.7.2.zh-CN.md`。

## 变更内容

- **控制面防卡死看门狗与失联自愈**
  - 在 `AutomaticRouteHealthRecoveryPolicy` 中新增 `providerUnresponsiveThreshold = 3` 与 `providerUnresponsiveCooldown = 300`；连续无应答达到阈值且非冷却期时返回 `.reconnectProvider`。
  - `TunnelManager` 维护 `consecutiveProviderUnresponsiveCount`，在收到有效响应时清零，在超时或缺少响应时递增。
  - 遥测轮询异常与自动路由健康刷新中介入失联自愈检查，避免客户端因单次 XPC 挂起而陷入假死状态。
  - 透明代理扩展端在 `handleAppMessage` 中引入 15 秒看门狗定时器，超时返回 `.unavailable`，防止扩展端处理队列停滞。
- **UDP 对端重置（code=2）日志降噪**
  - 精准识别 `NEAppProxyErrorDomain` code 2（`NEAppProxyFlowError.peerReset`），将其从原 `failure` 级别降为 `verbose` 级别。
  - 短连接 UDP 与 TCP 握手失败为 `FlowIOError.closed` 时统一降为 `verbose`，消除 Console 日志噪点与污染。
- **宿主 App 关键运维诊断日志落盘**
  - `TunnelManager` 引入 `DiagnosticLogCenter.current.log`，将失联自愈恢复、重连等关键运维事件同步落入 2MB 轮转日志（`app.log`），方便导出诊断包分析。
- **流量统计字段兼容性补全**
  - `DiagnosticAggregator` 补齐 `.bytesUpstream(Int)` 与 `.bytesClient(Int)` 分支，保证数据链路模型完整性。
